# 第 3 步：定声明

## 产出

公共头文件、类型与函数声明、命名、声明顺序和声明注释。声明要能让调用方在不读 `.cpp` 的情况下知道怎么用、什么时候失败。

## 通用情况

- 语言固定 C++20，不使用 C++23 特性；头文件用 `#pragma once`（本项目对 Google 的书面偏离之一）。
- 命名按 `references/naming.md`：类型与函数 PascalCase，变量与参数 snake_case，类成员尾随 `_`，常量与枚举子 `k` 前缀。
- 声明顺序按 `references/declaration-order.md`：类型 → 静态常量 → 工厂 → 构造/赋值/析构 → 其他函数 → 数据成员。
- 公共头文件自包含：自身需要的头都直接包含，不依赖调用方的包含顺序。
- 单参数构造函数写 `explicit`；可查询的成员函数加 `[[nodiscard]]`；默认成员初始化写在声明处，不在构造函数里重复。
- 可预期的失败用返回值表达（结果类型、`bool` + 输出参数、`std::optional`）；合同违反才在声明注释里写清抛出的异常类型。
- 声明注释写契约：参数范围、返回值、失败方式、所有权。不要写实现步骤。
- `std::format` 用于组合消息；声明里不要承诺 `std::print`（C++23）。

## 情况

**新增类型**：先判断是聚合 `struct`、有不变量的 `class`，还是 `enum class`；接口多于数据且有 invariant 时用 `class`，纯数据传递用 `struct`。

**改公共接口**：先找所有调用方；改签名、改返回类型、改异常合同都算破坏性变更。能加默认参数或重载时优先加，不要静默改变旧调用的含义。

**异常合同**：构造函数、`Get` 类查询、解析函数最容易违反合同；在声明注释里写「当……时抛出 `std::invalid_argument` / `std::out_of_range`」，不要只写「可能抛异常」。

**注释**：声明注释用 `///`，只写调用方需要知道的；实现细节留给 `.cpp`。文件头、章节横幅和 TODO 的格式见 `references/comments.md`。

## 正反例指针

- 命名、访问器、语义角色：`examples/naming.md`。
- 异常合同与返回值选择：`examples/exceptions.md`。
- 声明注释写成了实现说明：`examples/comments.md`「声明注释」。
