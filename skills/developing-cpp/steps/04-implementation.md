# 第 4 步：定实现

## 产出

`.cpp` 中的函数体、操作顺序、分组空白和实现注释。实现只兑现第 1 步的行为和第 3 步的声明，不新增公共接口。

## 通用情况

- 函数保持短小；一个函数只做一件事。超过约 40 行时先找可以命名的中间步骤，不要用注释把长函数切成几段。
- 按「准备 → 操作 → 收尾」排列语句，用空行分组；组与组之间的空行表达阶段，不用大段叙述。
- `.cpp` 第一个 include 是自己的配对头，然后直接包含本文件用到的标准库头；不要依赖公共头替本文件转发声明。`misc-include-cleaner` 会把这类缺失当成错误。
- 实现注释只写「为什么这样做」「这里的边界条件」「这样排序的代价」，不复述代码。
- 错误处理：可预期失败返回结果类型；合同违反抛异常。捕获异常时按 `const` 引用捕获，只处理能处理的类型，其余继续抛。
- 组合输出用 `std::format`，再写入 `std::cout` / `std::cerr`；不要在库实现里直接打印。C++20 没有 `std::print`。
- 不写 C 风格强制转换；用 `static_cast` / `std::bit_cast` 等具名转换。
- 所有权用 `std::unique_ptr`；没有共享所有权的理由时不用 `std::shared_ptr`。
- 只改注释时，不改可观察行为；只改实现时，不改公共声明。两者同时需要时，先改声明，再改实现。

## 情况

**新实现**：先写最短的直路，让第 1 步的验收通过；重复出现两次以上再抽函数。不要预埋未使用的抽象。

**修缺陷**：先加一个能复现的测试或最小输入，再改实现；修完删掉临时调试输出，保留测试。

**重构**：一次只动一种东西（改名、抽函数、换容器）。每步都让测试保持绿色；行为句不变。

**异常边界**：库内部可以让合同异常向上传播；程序入口捕获 `std::exception`，用 `std::format("错误: {}", error.what())` 打印，返回非零退出码。不要吞掉异常后继续用无效状态。
