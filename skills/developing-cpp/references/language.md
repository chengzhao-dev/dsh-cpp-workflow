# 语言基础与对象语义

这里只写“换一台机器、换一个编译器仍然成立”的 C++11–C++23 语言规则；示例默认 C++23，C++11/14/17/20 项目按声明降级。项目专属类型、协议字段和构建目录不在本文件。

## 值与对象

- 类型决定允许的操作和表示；对象是某类型的一块存储；值是可以复制、比较、传递的内容。
- 变量有名字、类型、存储期和作用域。局部变量在离开作用域时销毁；`static` 局部变量在首次执行到声明时初始化，程序结束时销毁。
- 声明让名字可见，定义分配存储或给出函数体。一个实体可以声明多次，但只能定义一次；头文件只放声明，定义放 `.cpp`。
- 引用是已有对象的别名，必须初始化，不能重新绑定；指针可以为空，也可以改指向。接口优先用引用表达“必须存在”，用指针表达“可以不存在”。
- `*this` 不用于复制当前对象：要一份副本就直说语义（如“推演落子”只读原数据，或显式写一个复制函数）。`return *this` 仍只属于赋值运算符，井字棋没有这种运算符。

## 初始化与列表初始化

默认用花括号初始化，只在需要对比、`auto` 推导或赋值语义时用 `=`：

```cpp
int count{};                       // 值初始化，0
std::vector<int> values{1, 2, 3};  // 列表初始化
std::string name = "demo";         // 拷贝初始化，类型明确
auto total = 0.0;                  // auto 只能用 =，不能用 {}
```

- `T value{}` 做值初始化：内置类型得 0，类类型调用默认构造函数。
- 花括号禁止窄化转换：`int x{3.5}` 编译失败，`int x = 3.5` 静默截断。需要截断时显式 `static_cast<int>(3.5)`。
- `std::vector<int> values(3)` 是三个 0；`values{3}` 是一个元素 3。两种括号语义不同，不要凭习惯混用。
- 类成员在声明处写默认成员初始化（NSDMI）：标量 `count_{0}`，数组 `items_{}`，容器和类类型成员不写空 `{}`。
- 构造函数初始化列表按成员声明顺序执行，不按书写顺序；初始化列表顺序与声明顺序保持一致，避免依赖未初始化成员。

## `auto` 与类型推导

- `auto` 适合“右侧类型显然且无关紧要”的局部变量，例如迭代器、`make_unique` 结果、范围 `for`。
- 公共接口、类成员、函数返回类型写显式类型；返回值需要隐藏实现细节时才可以写 `auto`，且头文件里要能看出契约。
- `auto` 会丢掉顶层 `const` 和引用：`auto value = const_ref` 得到副本；需要引用时写 `const auto&`。
- 结构化绑定 `auto [key, value] : map` 中，`key` 是副本；要避免复制时写 `const auto& [key, value]`。

## `const`、`constexpr`、`consteval`、`constinit`

| 关键字 | 承诺 | 典型位置 |
| --- | --- | --- |
| `const` | 初始化后不能通过这个名字修改 | 局部变量、参数、成员函数尾部 |
| `constexpr` | 能在编译期求值（满足条件时） | 常量、函数、构造函数 |
| `consteval` | 必须在编译期求值 | 编译期校验函数 |
| `constinit` | 静态存储期变量在编译期完成初始化 | 全局/静态变量 |
| `inline constexpr` | 头文件里可共享的编译期常量，避免 ODR 问题 | 命名空间作用域常量 |

- 共享常量写在头文件的命名空间作用域：`inline constexpr int kMaxRows = 3;`，不要用 `#define`。
- `constexpr` 函数的定义要放在头文件里，否则其他翻译单元无法在编译期调用。
- 不要给所有函数加 `constexpr`；只有确实需要在编译期使用、且实现满足约束时才加。
- `constinit` 只保证初始化时机，不保证不可修改；需要不可修改时同时写 `const`。
- C++20 起 `constexpr` 函数可以包含循环、局部变量和部分动态分配，但不要借此把运行期逻辑塞进编译期。

## 表达式与比较

- 比较写成“变量在左、常量在右”：`if (id < kTaskCount)`，不写 Yoda 条件 `if (kTaskCount > id)`。编译器会在漏写 `=` 时给出警告，可读性也更好。
- 混合优先级的算术表达式加括号：`(a + b) * c`，不依赖读者记忆优先级。`readability-math-missing-parentheses` 会检查。
- 区间用半开区间 `[low, high)`；判空用 `empty()`，不要用 `size() == 0`。
- 逻辑表达式按语义分组，一组一个括号；不要把多个否定串成一行。
- 自增自减单独成句；不要在同一个表达式里对同一对象多次修改，那是未定义行为。

## 函数、参数与返回值

- 函数名用 PascalCase，动词开头；查询用 `Is` / `Has` / `Can` / `Get` / `Find`，转换用 `SourceToTarget`。
- 输入参数默认按值传小对象、按 `const&` 传大对象；需要修改调用方对象时用引用参数，并在名字或注释里标 `[out]`。
- 优先返回值而不是输出参数；需要返回多个值时用 `struct` 聚合，不用多个 `bool` 输出参数。
- 返回容器或大对象时按值返回，依赖 RVO / 移动；不要返回局部对象的引用或指针。
- 单参数构造函数加 `explicit`，除非确实需要隐式转换；转换运算符也加 `explicit`。
- 不在虚函数上写默认参数；默认参数在静态类型处绑定，派生类改默认值会造成意外。
- 函数只做一件事；超过一屏时先找可命名的子步骤，不要用注释给长函数分段。

## 类、结构体与特殊成员

- `struct` 用于公开数据的聚合；`class` 用于维护不变量、隐藏表示。两者只差默认访问权限，按语义选。
- 数据成员默认私有；需要暴露只读视图时提供 `const` 成员函数，不返回可变内部引用。
- 单参数构造函数用 `explicit`；构造函数失败时抛异常，不留下半初始化对象。
- 特殊成员（构造、析构、拷贝、移动）在头文件声明，在 `.cpp` 定义；只有默认实现足够且零参数时才写 `= default`。
- 定义了析构函数、拷贝构造或拷贝赋值之一时，认真考虑其余特殊成员；用 `= delete` 明确禁止不需要的操作。
- 多态基类析构函数必须是 `virtual` 或 `protected`；否则通过基类指针删除派生对象是未定义行为。
- 不在构造函数里调用虚函数；此时派生部分还没构造完。

## RAII、所有权与移动

- 资源获取即初始化：用对象生存期管理内存、文件、锁、套接字；析构函数负责释放。
- 默认用 `std::unique_ptr<T>` 表达独占所有权；需要共享所有权时才用 `std::shared_ptr<T>`，并用 `std::weak_ptr` 打破循环。
- 不写裸 `new` / `delete`；需要动态数组时用 `std::vector`，需要单个对象时用 `std::make_unique`。
- 移动是“把资源指针转走并置空源对象”的转换；`std::move` 只是 `static_cast<T&&>`，本身不移动任何东西。
- 移动后的对象处于有效但未指定状态；只能重新赋值或销毁，不要读取它的值。
- 移动构造函数和移动赋值标记 `noexcept`，否则 `std::vector` 等容器在扩容时可能选择拷贝。
- 返回值直接 `return value;`，不要 `return std::move(value);`；后者阻止 RVO。

## 模板、概念与 CTAD

- 模板定义放头文件；`.cpp` 里的模板实例化只对当前翻译单元可见。
- C++20 用概念约束模板参数，把错误从实例化深处提前到调用点：

```cpp
template <typename T>
concept Numeric = std::is_arithmetic_v<T>;

template <Numeric T>
T Clamp(T value, T low, T high) {
  if (value < low) return low;
  if (value > high) return high;
  return value;
}
```

- 概念只表达语法和语义约束，不替代文档；错误消息要能让调用者知道违反了哪条约束。
- CTAD（类模板实参推导）用于局部变量和明显场景：`std::pair pair{1, 2.0};`；公共接口写显式模板实参，避免推导规则变化影响契约。
- 不用模板做运行期分支；需要运行期多态时用虚函数或 `std::variant`。

## 检查清单

- [ ] 初始化方式统一，窄化转换被编译器拦住。
- [ ] `auto` 只出现在类型显然的局部变量；公共接口有显式类型。
- [ ] 共享常量用 `inline constexpr`，没有宏常量。
- [ ] 比较不是 Yoda 形式，混合优先级有括号。
- [ ] 资源由 RAII 管理，没有裸 `new` / `delete`。
- [ ] 特殊成员声明与定义位置正确，移动操作 `noexcept`。
- [ ] 模板约束用概念表达，定义在头文件。
