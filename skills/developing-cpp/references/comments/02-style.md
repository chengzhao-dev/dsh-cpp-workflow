# 注释的结构、版式与措辞

本文件接 `references/comments/01-comment-rules.md`：那一份写内容，这一份写注释放在哪一层、用什么符号、按什么宽度与标签排版，以及怎么删复述、统一句式。两份文件对同一句给出不同说法时，内容层以 01 为准，符号、宽度、标签排版与措辞层以本文件为准；本文件不重复定义内容规则，只写排版落点。判不准用词时查 `references/comments/glossary/01-comment-terms.md`。

## 结构：放在哪一层、哪一行

- 文件头与声明注释用设置里选定的符号（默认 `///`，也可 `/** ... */`）：头文件里的类型、函数声明、命名空间常量、公开与私有数据成员，以及文件头的 `@file`/`@brief` 块。调用方和 Doxygen 从这里取契约。
- `///<` 只给枚举项和 `struct` 短字段的行尾；不要写在赋值、`break` 或普通语句后面。
- `//` 给函数体内的阶段说明、局部变量、守卫理由和普通语句行尾；这些注释不接 Doxygen 文档。
- 函数体里几条语句各写一件不同的事时，事实写在该语句的行尾；整段共有的次序或防护理由写在段首一句，不写半句总起让读者自己配到某一行。
- `//` 也给工具指令与别种文件：`// NOLINTNEXTLINE(...)`、`#endif  // MACRO`，以及 CMake、YAML 等非 C++ 文件。
- 判断看位置：声明写契约，用选定的文档符号；实现写理由，用 `//`。
- 位置固定：文件头在最上方；类型注释紧贴类型声明；特殊成员（构造、析构、拷贝与移动）排在其他函数之前；函数注释紧贴函数声明；数据成员的主注释紧贴声明上一行，不写行尾补充。
- 类数据成员（含私有）的主注释默认用 `///`，选 block 时随设置；行尾 `///<` 只给枚举项和 `struct` 的短字段。
- 注释和它说明的声明之间不留空行；同一个声明块内，空行只用来分组。

### 文件头

每个手写源文件开头写一段 doxygen 文件头：第一行写 `@file <文件名>`；第二行可以留一行空注释，下一行写 `@brief` 一句话说明这个文件定义或实现什么；头文件再用一行空注释隔开后，只写本文件自己的组成部分或边界；实现文件只有 `@file` 与 `@brief` 两行也合规，有额外边界时才补这一段。类型定义型头文件的 `@brief` 直接写本文件定义的类型名，多个类型用「与」并列，以「类型定义。」收句；空行后一段只写本文件的组成或这个类型的职责：按声明顺序逐项列「中文概念 `类型名`」，或用「类型名：是什么、提供什么」写清它的边界。这一段用名词短语，不以「封装了」起句，不写「相关」「实体」这类空词，也不写「回答……事实」这类拟人句；其他头文件写本文件定义什么，实现文件以「实现」收句，只实现成员函数时写「…成员函数实现。」，不写「文件包含」这类标签，也不写行为清单。本插件的检查器要求 `@file` 的参数与文件名逐字相同；Doxygen 本身允许省略参数或只写部分路径。`@brief` 默认始终写出，设置里显式关闭时整条省略；`@author`、`@date`、`@copyright`、`@version` 默认关闭，项目设置里打开并填了非空值才写出，空值整条省略；检查器把这四项列为隐私标签，确实要写时用 `--allow-tag` 放行；作者、年份和变更史按团队约定填写，不填就不出现在源码里。删掉把读者指去另一个头文件、另一个目录或另一层的句子，也删掉「这一层不负责什么」。不写外部资料路径。

```cpp
/// @file square.h
///
/// @brief 方格与方格值类型定义。
///
/// 方格的值 `SquareValue` 与方格 `Square`。
```

选择块注释时，同一段写成：

```cpp
/**
 * @file square.h
 *
 * @brief 方格与方格值类型定义。
 *
 * 方格的值 `SquareValue` 与方格 `Square`。
 */
```

实现文件对应写（`@brief` 与头文件对应，写「…实现。」，只实现成员函数时写「…成员函数实现。」，不列成员）：

```cpp
/// @file square.cpp
///
/// @brief 方格成员函数实现。
```

- C++ 源文件用以上格式；CMake 用 `#`，YAML/JSON 用 `#`。
- 超过约 200 行的文件用空行分成几节，每节的说明写在一行 `//` 上，与下一节代码之间空一行，不画装饰线；不要写成 `///`，否则会被当成下一个声明的文档注释。
- 文件头按 `@file`、`@brief` 的顺序写，各占一行，后面只写本文件的范围与组成，不写实现步骤；默认不写作者与变更史，设置里填了非空值才写。长度见 `references/comments/01-comment-rules.md` 的「长度预算」。

## 版式：符号、宽度与标签

- 注释符号在插件设置里选择：`///` 是默认写法，`/** ... */` 是另一种 Doxygen 写法；文件头与声明注释统一用同一种，`///<` 行尾与函数体内的 `//` 除外。块注释每行以 ` * ` 对齐，收尾单独一行 ` */`。
- 行宽跟文件最近的 `.clang-format` 的 `ColumnLimit` 走：从文件所在目录向上查找，到工程根为止；都没有时按 120 列，中文按两列、tab 按 4 列计。`checking-comments.mjs` 按同一规则取宽度。源码会被读者正文逐字摘录进 Markdown 时，代码行与注释行宽都收到书稿代码块的 100 列，比 `ColumnLimit` 更严；超宽时把行尾整块移到上一行或下一行，不按字符硬折。`checking-comments.mjs` 仍只按 `ColumnLimit` 判。
- Doxygen 文档块：摘要与详细描述之间空一行注释（一行 `///`）；段落之间空一行注释；摘要或详细描述与标签块之间空一行注释（无详细描述时摘要后也要空一行）；标签按参数、返回值、异常、前置条件、说明分组，组与组之间空一行注释，同一组内的标签连续排列。`@param`、`@tparam` 一组，`@return`、`@retval` 一组，`@throws` 一组，`@pre`、`@post` 一组，`@note` 一组。Doxygen 不规定这些组的先后，按注释中的书写顺序渲染；本工作流默认按参数 → 返回值 → 异常 → 说明排列，`@note` 解释提前返回或前置条件时可放在 `@return` 前，同一文件保持一致。
- 注释换行：声明、文件头与类型/函数文档注释默认写成语义段落，不按「一句一行」切碎；函数体内的 `//` 按实现注释规则，每个阶段一句。同一契约或同一组不变量的连续说明写成一段，段内按列宽在分句处折行，折行时标点跟随前句，不放在行首；互不依赖的事实、条件或结果各自成段，用一行 `///` 隔开。段落以一个主题为限，首句应能独立作摘要；brief 只写一句，详细描述另起一段。禁止把互不相关的单句硬拼成一段，也禁止把连续契约拆成多行短句；不把一句话拆成一个词一行。
- 列表：同一段注释要列两种以上情况时，先写一句总起句说明这些项共同描述什么，紧接列表（中间不空行），每项一行；列表项比正文再缩进两格，让总起句与各项在源码里就能看出层级：Doxygen 写 `///   - `，块注释写 ` *   - `；注释整体有缩进时，列表项随正文一起平移。列表后按段落需要留空行。返回值列表（`@retval`）例外，可直接列值。`checking-comments.mjs` 会报 `list-indent`。
- 中英文混排：中文与标识符、英文缩写、数字之间各留一个半角空格，标识符与中文标点之间不留空格；中文句用全角标点；标识符保持源码原样，不在名字中间插空格，也不写成全角。例：`/// 传入的是 kEmpty，或方格已有值时，都不写入。` 标签后的说明同样按这个句式写。
- 引用的命令、格式串、字面量按原样保留，不按中文标点改写；中文说明与字面量之间留空格。
- 行尾注释与代码之间空两格；`///<` 只接在枚举项和 `struct` 短字段声明行尾。
- `@param`、`@return`、`@throws` 标签保持英文；`@param` 后先写参数名，再写一句；`@return` 里的具体返回值（`std::nullopt`、枚举值）用反引号；布尔值 true/false 原样写，不加反引号；说明返回值怎么读。
- `TODO:` 后先写定位（阶段名或 issue 号），再写一个短横线，再写动作；不写 `TODO(某人)`，不写没有动作的 TODO。
- 构建与编辑器配置的注释见 `building-cpp` 与 `engineering` 技能。
- 禁止：大段表格、装饰图案、表情；外部资料路径、跨仓库引用、团队流程；注释掉的代码；注释元叙述（「其余内容见某处」「两处不重复」）。
- `///` 与 `@param` 不进入 `.qmd`、YAML、CSS。
- 函数体内不写 `///` 或 `/** ... */`；`//` 用于实现说明与 `// NOLINTNEXTLINE(...)` 这类工具指令。

## 措辞：删复述，统一句式

- 类型第一句是名词短语；布尔查询、普通函数、枚举项的句式与内容见 `01-comment-rules.md` 的「内容」「函数」两节；本文件只统一用词与句式落点。
- 特殊成员保留标签（`默认构造函数：`、`析构函数：` 等），后置条件与职责见 01 的「构造函数与析构函数」节；禁止只写「构造函数：创建对象」这类没有后置条件或职责的句子，也不复述类名、签名、成员清单。
- 领域尺寸与成员功能清单不写进类型注释，判据见 01 的「类型」节。
- 同一事实只写一处：声明注释、实现注释、书稿和 README 不各讲一遍。
- 删注释前先对照 01「内容」节要求保留的后置条件、类级生命周期、轴向和哨兵；这些不因精简删除。
- 注释写给维护者，正文写给读者；设计理由、方案比较与算法取舍写在正文或实现注释里，公开接口只留契约。
- 非拥有视图成员的类级生命周期写在类型注释，`@param` 仍要说明数组与每个元素指向的字符都覆盖模型，见 01 的「类型」与「函数」节。
- 注释正文优先不用括号补充。能用逗号、冒号或独立短句改写时不用括号；不要用括号塞入第二个独立事实。代码语法必需的括号保留，例如 `CountOptions()`、`std::array<int, 3>`。
- 禁止用注释代替类型、`const` 或 `[[nodiscard]]`。
- 只改注释时按 01 末节的回读清单复核，并运行 `checking-comments.mjs`；检查器只兜住 01 覆盖表列出的条目，其余靠人工。

### 术语与用词

`references/comments/glossary/01-comment-terms.md` 列「位置/坐标」「方格/棋盘」「更新/写入」「副本」「越界」与 `square.h`/`square.cpp` 这一组文件的用词。

- 术语表给默认译法与近义词边界，不是逐字模板：源码注释按类型、成员、函数和上下文选词，已经更准确地贴合声明或语境的句子，不为了对齐术语表改回表里的说法。

- 无生命对象用「个」作量词，写「一个电脑对手」「输入、输出与诊断三个流」，不写「一只电脑」「三股流」；生命周期动作写清对象与结果，写「换局时只撤回上一局的落子」「换难度时只改档位」，不写缺宾语的「只撤回」「只调整」。
- 领域行话第一次出现时写通用说法；「一次落子」就写全，不缩成行话简称；电脑的回应写「回应落子」，不写「应手」。不假定读者读过书稿或上一章；同一文件只留一个叫法。
- 先用领域名词：集合叫「历史」就写「落子历史」，不写「已经下过的每一次落子」这种展开式；名字已经给出名词时，重复名词比重新描述集合更短，也更统一。
- 类型与函数的第一句不能用未解释的行话代替定义。先写读者能核实的动作或对象，再补项目里的简称。
