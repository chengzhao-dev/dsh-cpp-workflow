# 注释的结构、版式与措辞

本文件接 `references/comments/01-comment-rules.md`：那一份写内容，这一份写注释放在哪一层、用什么符号、按什么宽度与标签排版，以及怎么删复述、统一句式。判不准用词时查 `references/comments/glossary/01-comment-terms.md`。

## 结构：放在哪一层、哪一行

- 文件头与声明注释用设置里选定的符号（默认 `///`，也可 `/** ... */`）：头文件里的类型、函数声明、枚举项、公开与私有数据成员，以及文件头的 `@file`/`@brief` 块。调用方和 Doxygen 从这里取契约。
- `///<` 只给枚举项和 `struct` 短字段的行尾；不要写在赋值、`break` 或普通语句后面。
- `//` 给函数体内的阶段说明、局部变量、守卫理由和普通语句行尾；这些注释不接 Doxygen 文档。
- `//` 也给工具指令与别种文件：`// NOLINTNEXTLINE(...)`、`#endif  // MACRO`，以及 CMake、YAML 等非 C++ 文件。
- 判断看位置：声明写契约，用选定的文档符号；实现写理由，用 `//`。
- 位置固定：文件头在最上方；类型注释紧贴类型声明；特殊成员（构造、析构、拷贝与移动）排在其他函数之前；函数注释紧贴函数声明；数据成员的主注释紧贴声明上一行，不写行尾补充。
- 类数据成员（含私有）的主注释用 `///`；行尾 `///<` 只给枚举项和 `struct` 的短字段。
- 注释和它说明的声明之间不留空行；同一个声明块内，空行只用来分组。

### 文件头

每个手写源文件开头写一段 doxygen 文件头：第一行写 `@file <文件名>`，第二行写 `@brief` 一句话说明这个文件定义或实现什么，用一行空注释隔开后，只写本文件自己的组成部分或边界。类型定义型头文件写「…相关类型定义。」，空行后以「封装了」起句，逐项写「中文概念 `类型名`」，顺序与声明一致；其他头文件写本文件定义什么，实现文件以「实现」收句。不写「文件包含」这类标签，也不写行为清单。本插件的检查器要求 `@file` 的参数与文件名逐字相同；Doxygen 本身允许省略参数或只写部分路径。`@brief` 始终写出；`@author`、`@date`、`@copyright`、`@version` 的开关出厂打开，只有填了非空值才写出，空值整条省略；作者、年份和变更史按团队约定填写，不填就不出现在源码里。删掉把读者指去另一个头文件、另一个目录或另一层的句子，也删掉「这一层不负责什么」。不写外部资料路径。

```cpp
/// @file square.h
/// @brief 方格相关类型定义。
///
/// 封装了方格的值 `SquareValue` 以及方格实体 `Square`。
```

选择块注释时，同一段写成：

```cpp
/**
 * @file square.h
 * @brief 方格相关类型定义。
 *
 * 封装了方格的值 `SquareValue` 以及方格实体 `Square`。
 */
```

- C++ 源文件用以上格式；CMake 用 `#`，YAML/JSON 用 `#`。
- 超过约 200 行的文件用空行分成几节，每节的说明写在一行 `///` 上，不画装饰线。
- 文件头 3–7 行，实现文件可只有 `@file` 与 `@brief` 两行；`@file` 与 `@brief` 各占一行，后面只写本文件的范围与组成，不写实现步骤、作者和变更史。

## 版式：符号、宽度与标签

- 注释符号在插件设置里选择：`///` 是默认写法，`/** ... */` 是另一种 Doxygen 写法；文件头与声明注释统一用同一种，函数体内仍只用 `//`。块注释每行以 ` * ` 对齐，收尾单独一行 ` */`。
- 行宽跟文件最近的 `.clang-format` 的 `ColumnLimit` 走：从文件所在目录向上查找，到工程根为止；都没有时按 Google 默认 80 列，中文按两列计。`checking-comments.mjs` 按同一规则取宽度。
- Doxygen 文档块：摘要与详细描述之间空一行注释（一行 `///`）；段落之间空一行注释；详细描述与标签块之间空一行注释；标签按参数、返回值、异常、说明分组，组与组之间空一行注释，同一组内的标签连续排列。`@param`、`@tparam` 一组，`@return`、`@retval` 一组，`@throws` 一组，`@note` 一组。
- 注释换行：声明、文件头与类型/函数文档注释默认写成语义段落，不按「一句一行」切碎；函数体内的 `//` 按实现注释规则，每个阶段一句。同一契约或同一组不变量的连续说明写成一段，段内按列宽在分句处折行，折行时标点跟随前句，不放在行首；互不依赖的事实、条件或结果各自成段，用一行 `///` 隔开。段落以一个主题为限，首句应能独立作摘要；brief 只写一句，详细描述另起一段。禁止把互不相关的单句硬拼成一段，也禁止把连续契约拆成多行短句；不把一句话拆成一个词一行。
- 列表：同一段注释要列两种以上情况时，先写一句总起句说明这些项共同描述什么，紧接列表（中间不空行），每项一行；列表项比正文再缩进两格，让总起句与各项在源码里就能看出层级：Doxygen 写 `///   - `，块注释写 ` *   - `；注释整体有缩进时，列表项随正文一起平移。列表后按段落需要留空行。返回值列表（`@retval`）例外，可直接列值。`checking-comments.mjs` 会报 `list-indent`。
- 中英文混排：中文与标识符、英文缩写、数字之间各留一个半角空格，标识符与中文标点之间不留空格；中文句用全角标点；标识符保持源码原样，不在名字中间插空格，也不写成全角。例：`/// 传入的是 kEmpty，或方格已有值时，都不写入。` 标签后的说明同样按这个句式写。
- 引用的命令、格式串、字面量按原样保留，不按中文标点改写；中文说明与字面量之间留空格。
- 行尾注释与代码之间空两格；`///<` 只接在枚举项和 `struct` 短字段声明行尾。
- `@param`、`@return`、`@throws` 标签保持英文；`@param` 后先写参数名，再写一句。
- `TODO:` 后先写定位（阶段名或 issue 号），再写一个短横线，再写动作；不写 `TODO(某人)`，不写没有动作的 TODO。
- `.clang-format`、`.clang-tidy`、`.clangd`、CMake 的配置项旁边写「为什么这样设」，不写「这一项是什么」；配置注释贴在被解释的键上方。
- 禁止：大段表格、装饰图案、表情；外部资料路径、跨仓库引用、团队流程；注释掉的代码；注释元叙述（「其余内容见某处」「两处不重复」）。
- `///` 与 `@param` 不进入 `.qmd`、YAML、CSS。
- 函数体内不写 `///` 或 `/** ... */`；`//` 用于实现说明与 `// NOLINTNEXTLINE(...)` 这类工具指令。

## 措辞：删复述，统一句式

- 类型第一句是名词短语；布尔查询写「主体是否状态」，句中有「是否」，句首不用「检查」「判断」「校验」「验证」，`operator==` 用「相等运算符。」；普通函数第一句写结果或失败方式。
- 特殊成员保留标签（`默认构造函数：`、`析构函数：` 等），但禁止只写「构造函数：创建对象」这类没有后置条件或职责的句子，也禁止复述类名、签名、成员清单。
- 禁止在类型注释里写领域尺寸（3×3、九个方格、边长）；尺寸由成员声明和常量表达。
- 禁止把成员功能清单按声明顺序抄一遍；函数契约写在各自函数上。
- 同一事实只写一处：声明注释、实现注释、书稿和 README 不各讲一遍。
- 删掉注释后读者不会做错事、或注释只重复签名时，删；但 `01-comment-rules.md` 内容节要求保留的后置条件、类级生命周期、轴向和哨兵不在此列。
- 只改注释时仍走第 3、4 步，然后回读：文件头 → 类型（名词短语 + 只有类的不变量与生命周期）→ 特殊成员（标签 + 后置条件/职责）→ 函数（结果/失败方式/成立条件 + 参数）→ 数据成员（只读上一行 `///`：名词 + 全角冒号 + 约定；行尾不应有注释）→ 实现（每个空行阶段的边界或理由）→ 术语与新符号是否真实存在 → 运行 `checking-comments.mjs` 兜底。
- 注释写给维护者，正文写给读者；设计理由、方案比较与算法取舍写在正文或实现注释里，公开接口只留契约。
- 禁止用注释代替类型、`const` 或 `[[nodiscard]]`。

### 术语与用词

`references/comments/glossary/01-comment-terms.md` 列「位置/坐标」「方格/棋盘」「更新/写入」「副本」「越界」与 `square.h`/`square.cpp` 这一组文件的用词。

- 领域行话第一次出现时写通用说法；「一次落子」就写全，不缩成行话简称；电脑的回应写「回应落子」，不写「应手」。不假定读者读过书稿或上一章；同一文件只留一个叫法。
- 先用领域名词：集合叫「历史」就写「落子历史」，不写「已经下过的每一次落子」这种展开式；名字已经给出名词时，重复名词比重新描述集合更短，也更统一。
- 类型与函数的第一句不能用未解释的行话代替定义。先写读者能核实的动作或对象，再补项目里的简称。
