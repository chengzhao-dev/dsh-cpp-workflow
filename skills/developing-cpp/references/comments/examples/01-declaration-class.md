# 正反例：类型注释：概念与约定，不是功能清单

**差**：

```cpp
/// 棋盘。
///
/// 提供检查坐标区间、检查棋盘方格是否为空、获取棋盘方格类型、放置棋子、清空棋盘和判定终局的功能。
/// 棋盘为 3 行 3 列。
class Board {
```

问题有两处：把成员函数抄了一遍，接口一改就过期；「棋盘为 3 行 3 列」被拆成单独一句，读者不知道它在回答什么问题。

**差**（把别的类型和以后才发生的事都写进来）：

```cpp
/// 棋盘。
///
/// 棋盘只保存九个方格和规则判断，不含回合推进：谁该落子、落子被拒后怎么提示留在 Game。
///
/// 棋盘是值语义，可以自由拷贝；所有查询都是 const，对局和搜索可以交替读取同一棋盘。
class Board {
```

第二段说的是 `Game` 负责什么，读者读完仍不知道 `Board` 是什么，重构一次这句话就过期；后两段里的可拷贝、`const` 查询在类声明里已经写清，「搜索要读同一棋盘」还不是现在的调用方。读者真正需要的是这个类型是什么；方格数由成员声明表达，失败方式写在各自函数上。

**好**（纯数据与尺寸由成员表达）：

```cpp
/// 棋盘。
class Board {
```

**好**（类有不变量，第二段直接写不变量）：

```cpp
/// 一局对局。
///
/// 棋盘、当前玩家和落子历史同步推进；落子被拒时三者都不变。
class Game {
```

**差**（把别的类型的分工写进类型注释）：

```cpp
/// 方格：保存一个 `SquareValue` 的值容器。
///
/// 初始为空。`SetValue` 只更新存储的值，不检查当前值；
/// 占用与终局由 `Board` 与 `Game` 决定。`Square` 不依赖棋盘或对局类型。
class Square {
```

第二段在写 `Board` 与 `Game` 负责什么，又列了 `Square` 不做什么；这些边界由类型和调用方表达，注释只写 `Square` 是什么。

**好**（纯值容器只写一句）：

```cpp
/// 方格：保存一个 `SquareValue` 的值容器。
class Square {
```

初始状态写在默认构造函数，写入与清空条件写在 `SetValue`；类型注释不重复枚举取值，也不写别的类型负责什么。只有类有不变量时，才在第二段写不变量与生命周期。

纯数据结构和枚举只写一句名词短语；类有不变量，且第二段不是重复 `squares_`、`kRowCount` 这类领域尺寸时，才保留第二段。第二段直接写不变量，不加「限制：」这类标签。函数各自的契约下沉到函数注释，设计理由与分层写进书稿。
