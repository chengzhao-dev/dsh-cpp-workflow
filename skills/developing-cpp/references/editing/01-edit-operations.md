# 变更模型

三个技能共用这一份模型。操作决定从哪一步进、这次改动的范围多大；域决定改动落在哪一层。操作不是域，域也不是步骤。

## 三种操作

| 操作 | 判据 | 可以 | 不可以 |
| --- | --- | --- | --- |
| 写作（起稿） | 缺可观察行为、契约或事实 | 新增类型、函数、文件、target、环境轴；补后置条件与成员事实 | 发明项目没有声明的行为、命令、标准或目录 |
| 改写 | 可观察行为与契约不变，组织、顺序或位置不对 | 移动、删除、换序、重写块段；保留事实与论证线 | 新增事实、数字、命令、结论或行为；改变否定、条件、范围、时间、归属 |
| 润色 | 只改措辞、命名或注释 | 删复述、换词、拆句、统一术语 | 改结构、改事实、加句子或加信息；把可能或通常改成确定 |

## 判不准时

按顺序问，第一问为是就是写作：

1. 缺一个可观察行为、契约或事实吗？
2. 现有组织、顺序或位置，读者能走通吗？不能走通是改写。
3. 只改措辞、命名或注释，行为与结构会变吗？不会变是润色。

三问都否，是只读审查：只报告，不改文件，不调构建。

## 越界信号

- 润色时想补声明里没有的事实：停；改判写作，或把事实退回源码与用户。
- 改写时发现原句的事实、条件或数字有误：停；改写不修事实，报告后按写作处理。
- 写作时发现行为与边界都对、只是措辞差：从第 3 步按润色进，不重走前两步。
- 润色时发现两处注释讲同一件事：删重复属于润色，换位置属于结构。
- 一轮里三种操作都出现：按写作 → 改写 → 润色拆开，前一段落定并经检查再进下一段。

范围随任务定：单点修正只改判为不合格的一处；整段重构先定删留，再改块段，最后逐句。只读审查不改文件，按操作判缺什么，只报告；不调构建、渲染或回执。

## 四个域

四个域也叫四类改动；两种说法指同一组内容、结构、版式、措辞。域是操作内部的层次，不是第四种操作。

| 域 | 回答的问题 | 可以改 | 不能改 |
| --- | --- | --- | --- |
| 内容 | 这次要保证什么新事实或新行为？ | 行为、契约、后置条件、成员事实 | 已有事实、否定、条件、数字、引文 |
| 结构 | 它放在哪一层、哪个文件、什么顺序？ | 文件位置、模块边界、声明顺序、注释位置 | 行为、措辞、命名 |
| 版式 | 它长什么样？ | 缩进、行宽、空行、注释符号、标签格式 | 标识符、字符串、命令、语义 |
| 措辞 | 这句话是否准确、必要、可读？ | 命名、用词、句式、复述、术语统一 | 结构、事实、段落顺序、信息量 |

四域按「内容 → 结构 → 版式 → 措辞」推进。前一层没落定，不进入下一层；后一层发现前一层没做完，退回那一层，不在当前层补。`references/editing/02-rule-priority.md` 的五级次序是冲突时的判据：行为与契约 > 结构 > 清晰 > 一致 > 形式。

## 跨技能交接

源码 → `engineering` → `building-cpp`。一次改动同时碰到三层时，先定源码行为与边界，再写 target，最后配工具并跑检查；前一段结论落下再开下一段。只改注释时，声明注释 → 实现注释 → CMake 契约注释 → 构建诊断，逐层按四域走。

## 写作边界

- 不新增原文没有的事实、数字、命令、性能结论、引文和出处；不把「可能」「通常」「在本书里」改成确定说法；保留否定、条件、范围、时间和归属。
- 不写否定式能力边界：不列「不检查…」「不校验…」「不负责…」「不判断…」清单；前置条件写成「调用方保证…」「仅接受…」或 `@pre`。状态结果「不做修改」「保持不变」是本次调用的结果，不是能力边界。
- 同一概念只用一个首选词；术语、命令、标识符、路径、URL 与围栏内容不改。
- 注释写声明里看不出的事实；实现注释写为什么、边界与失败后果，不复述代码。

## 依据

- IPEd《Types of editing》把编辑分为 substantive editing、copyediting 与 proofreading；本模型把「写作、改写、润色」对应到「新增、重组、措辞」三档，版式独立成形式层。
- Google C++ Style Guide、LLVM Coding Standards 与 C++ Core Guidelines 的注释条目都要求写意图、用法与陷阱，不把代码翻译成自然语言。
- 这些资料只解释模型，不替代项目技能、`environment.json` 或用户明确要求。

## 何时打开

判不准操作或域、跨技能交接、或四域冲突时打开。只做单点润色且入口明确时不必打开；步骤文件已点名的条文仍按步骤打开。

## 通用自检

1. 操作判对了吗：这次是新增行为、重组结构，还是只改措辞？范围是单点还是整段？
2. 域判对了吗：这次只动一层，还是混了两层？混了时是否按内容 → 结构 → 版式 → 措辞拆开？
3. 事实有没有变：有没有新增数字、命令、结论、引文，或把「可能」「通常」改成确定？
4. 边界写正了吗：有没有「不检查…」清单？前置条件是否写成「调用方保证…」「仅接受…」或 `@pre`？
5. 原样保留了吗：术语、命令、标识符、路径、URL 与围栏内容是否未被改写？
6. 次序守住了吗：前一层是否已落定并经检查，后一层才开始？冲突是否按 `references/editing/02-rule-priority.md` 判？
