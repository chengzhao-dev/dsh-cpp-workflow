# 注释

注释按内容、结构、版式、措辞四节组织；文件头、类型、函数与实现注释是注释所在的位置，配置文件的注释另算。位置越靠外，越讲概念与契约；越靠里，越讲实现理由。同一件事只写一次。

四域不是四个步骤：操作决定从哪一步进，域决定这次改哪一层；两者的边界与次序见 `source/01-editing/01-edit-operations.md`。本节只写注释里的落点。

按四类改动查：内容决定写什么，结构决定放哪一层哪一行，版式决定符号、宽度与标签，措辞删复述、统一句式。四步都可能删句子，但后置条件和成员约定只有内容能定，措辞不得以「精简」为由删掉。

用词与术语见 `source/07-comments/glossary/comment-terms.md`：判不准时再开。

## 内容：只写声明里看不出的事实

- **第一句先写结果、保证或检查项**：类型用名词短语写它是什么；普通函数写正常返回什么、失败时返回什么或抛什么；布尔查询与 `operator==` 写「检查…是否…」。第一句不写「返回 true/false」；`@return` 仍要写明成立时返回 true、不成立时返回 false。条件、参数与实现理由放第二句以后。
- **不写否定式能力边界**：注释不列「不检查…」「不校验…」「不负责…」「不判断…」这类清单；只写本函数保证什么、调用方必须满足什么。前置条件写成「调用方保证…」「仅接受…」或 `@pre`，布尔查询只写检查什么。状态结果可以说「不做修改」「保持不变」，因为它描述的是这次调用的结果，不是能力范围。`scripts/checking-comments.mjs` 会报 `negative-scope`。
- 公共注释回答「这是什么」和「调用方必须遵守什么」；实现注释回答「为什么这样写」和「边界在哪里」。设计取舍、方案对比与演进历史写到书稿、README 或提交说明。
- 用中文散文写完整句子，句号结尾；标识符、标准库类型、`@param` 这类标签保持原文。
- 写之前三问：删掉这句，读者会误解设计或做错事吗？这句只是复述签名或代码吗？这个限制能不能由类型、`const` 或 `[[nodiscard]]` 表达？第一问为否就删，第二问为是就删，第三问为是就改代码。
- 命名、分文件、`enum class`、异常与结果类型这类全项目风格约定只写进项目文档与读者正文；注释不替项目解释风格。
- 状态结论必须带成立条件。「终局后空格仍在」没有说清哪种终局；写成「一方已三连而棋盘尚未占满时，空格仍然留着；平局时棋盘已满，没有空格」。删掉前提换来的短，不算润色。

### 类型：名词短语与不变量

对象是类、结构体、枚举和类型别名。第一句是名词短语：类写「这个类型是什么」，可用全角冒号补初始状态；纯数据结构和枚举写「这个取值表示什么」。

只有类有不变量，且不重复领域尺寸时，才加第二段。第二段直接写不变量与生命周期：初始状态、状态迁移、清空条件；生命周期写在类注释，不拆到成员注释。第二段用概念句写生命周期，不点成员函数名。不加「限制：」这类标签，也不写「这一层不负责什么」。纯数据结构和枚举不写第二句。

```cpp
/// 井字棋棋盘。
class Board {
```

禁止事项：

- 不写成员清单，不按声明顺序复述接口。函数各自的契约写在函数上。连 `Place`、`Clear` 这样的成员名也不写进类注释；生命周期用「空白格子才能放置」这类概念句。
- 不写「至多成功一次」「最多放置一次」这类次数结论：`Clear` 或清空之后状态可以再次变化，次数结论会失效；写当前操作与清空条件，例如「空白格子才能放置；清空后才能再次放置」。
- 不写跨类分工。边界靠类型与所有权表达，注释只写本类型保证什么。
- 不写类型系统已经表达的性质（`值语义`、`所有查询都是 const`）。
- 不写尚未发生的用法、方案对比与取舍论证、广告句。
- 纯数据结构不写「只保存…，不拥有…，不含…」这类否定式边界；这些由成员类型和所有权表达。
- 领域尺寸不写进类型注释：格子数由 `cells_` 的声明表达，棋盘边长由 `kRowCount`、`kColumnCount` 表达。
- 枚举与只承载数据的结构体：第一句是名词短语，写这个取值表示什么。状态枚举写「格子状态。」，结果枚举写「放置结果。」或「对局结果。」这类「<对象><属性>」；不用「表示…结果。」开头，也不写成「格子的状态。」「对局的结果。」这种带「的」的短语。行尾 `///<` 的句式见「枚举项与 `struct` 短字段：两种句式」。

### 构造函数与析构函数：先写标签，再写职责

特殊成员用标签开头：`默认构造函数：`、`拷贝构造函数：`、`移动构造函数：`、`析构函数：`；其他构造函数写 `构造函数：`。标签后写构造完成后的后置条件，或析构函数负责什么。`= default` 配合成员初始化器建立的不变量，签名上看不见，必须写成后置条件。只写读者能观察到的事实，不写「创建对象」「初始化成员」这类复述。

```cpp
/// 默认构造函数：每一格都是空格子。
Board() = default;
```

默认构造与析构可以只写一行：标签后直接写后置条件或职责。`= default` 的后置条件写在标签那一行就够，不再另起一段写「不抛异常」，也不为了注释加 `noexcept`。无参数、无返回值的动作只在签名看不出结果时再写一句，不把「不抛异常」当成这句；不写 `@throws` 就表示不抛。类注释已经写了初始状态时，默认构造函数只写「建立初始状态」，不重复具体值；类注释没写时，才在这里写后置条件。不写空的 `@param`、`@return`。有参数或有返回值的函数按下一节写标签，构造与析构不写 `@return`。标签说明这是哪一类特殊成员，不重复类名；非默认构造同样写建立的不变量与失败方式。

### 数据成员：上一行 `///`，先写名词再写约定

类数据成员的主注释写在声明上一行，统一用 `///`，私有成员也一样。第一句先写这个成员是什么，再在同一句里补类型和名字看不出、只属于这个成员的约定：轴向、单位、哨兵值、所有权、外部约定。初值含义、状态迁移与清空规则若属于类级不变量，写在类注释，成员注释不重复；成员注释保持一句，名字和类型已经说清时可以不写。

有补充时写成一句 `/// 名词：约定。`，冒号用全角 `：`，句号结束；修饰必须依附于被修饰的名词，不能单独占一行。行尾不写 `//` 或 `///<`；`///<` 只留给枚举项和 `struct` 的短字段。

```cpp
/// 棋盘格子数组：外层下标是行，内层下标是列。
std::array<std::array<CellState, kColumnCount>, kRowCount> cells_{};
/// 当前玩家：开局由 X 先手。
Player current_player_ = Player::kCross;
/// 棋盘状态：落子被拒时保持原值。
BoardState state_ = BoardState::kInProgress;
```

类的生命周期写在类注释，成员注释只留这个成员是什么：

```cpp
/// 格子：初始时为空。
///
/// 空白格子才能放置；清空后才能再次放置。
class Cell {
  /// 格子当前的状态。
  CellState state_{CellState::kEmpty};
};
```

`board_` 这类名字已经说明存放对象的成员不写「对局棋盘」；`cells_` 不写「存储…」这种把声明读一遍的句子，但上一行要先说它是棋盘格子数组，再补轴向与哨兵。`clang-format` 不会把行尾注释搬到上一行，位置由本规则和检查器保证。

### 枚举项与 `struct` 短字段：两种句式

枚举项与只承载数据的 `struct` 短字段用行尾 `///<`，同一枚举各行的 `///<` 对齐。每个枚举项的注释必须以枚举主体的同一个词开头，写成完整的状态或结果，不写只有谓语的片段。枚举的类型注释也用同一个主体词：`Player` 写「玩家：`kX` 或 `kO`。」，成员写「玩家为 X：先手」；不把类型注释改写成「对局的一方」。

- 完整句：`///< 格子为空`、`///< 对局由 X 获胜`
- 主体加类别与说明：`///< 格子状态未变更：传入的是 kEmpty 状态`、`///< 对局以平局结束`

两类都不收句号。冒号用全角 `：`；冒号前写主体与类别，冒号后写能核实的说明，两侧都不能为空。禁止「X 成线。」「尚未结束。」这类没有主体、只有谓语的片段；禁止空冒号（`///< 落子成功：。`）、禁止把说明写在类别前面（`///< 传入空棋盘格子类型，非法参数。`）。无冒号的行尾是一句完整的话，可以有句内逗号；有冒号时不得用逗号代替冒号。同一枚举要么每一项都写 `///<`，要么都不写；都写时两种句式可以混用。

### 函数：两段式契约

有参数或有返回值的函数写两段：第一段写结果、失败方式或检查项；第二段按签名把标签写齐。

1. 第一段：普通函数写正常返回什么、失败时返回什么或抛什么；布尔查询与 `operator==` 写「检查…是否…」。
2. 第二段：每个参数一条 `@param`；有返回值默认写 `@return`，成立条件已由函数名与返回类型说清时可省略；会抛才写 `@throws`；`@pre`、`@post`、`@retval`、`@tparam`、`@note`、`@see` 出厂开关打开；只在确有需要时写，不需要可在设置里关掉。

```cpp
/// 检查坐标能否放置状态，不修改棋盘。
///
/// @param pos 目标行列坐标。
/// @param state 要放置的格子状态，必须是 kX 或 kO。
/// @return 可以放置返回 kUpdated；越界、state 为 kEmpty 或目标格子是 X 或 O 时返回对应拒绝值。
[[nodiscard]] Cell::PlaceResult CheckPlaceable(Position pos, CellState state) const;
```

- 布尔查询与 `operator==`：第一句写「检查…是否…」；`@return` 写成「成立时返回 true；不成立时返回 false」，不写「否则」省略后半句。`Is`、`Has` 开头的名字与 `bool` 返回类型已经把成立条件说清时可省略 `@return`，不为了形式补一句同义反复。
- `@param` 每个参数都写，写范围、单位或所有权，不写「索引」这类同义反复；没有参数就不写空的 `@param`。会校验并抛出的参数写「待检查/读取/更新的坐标」，不把「棋盘内」当前置条件。
- `@return` 默认写，写返回值怎么读或失败时返回什么；返回类型与函数名已把条件说清时可省略，不要用「见上」或重复第一段。
- 查询函数（`Get` 开头）：第一句写「获取…」；`@return` 列出可能取到的值，枚举值在 `///` 里用反引号，例如 `kEmpty`、`kX` 或 `kO`。返回副本时第一句和 `@return` 都写「副本」，不写「该位置的格子」这类可读成引用的句子。
- 返回多个明确结果（如 `PlaceResult`、`BoardState`）时用 `@retval`，每个值一行，值与说明之间空一格，不做列对齐（Doxygen 每项独立成行，clang-format 不维护标签列宽）；只有一个返回值时用 `@return`，不把几种结果压进一句 `@return`。
- 更新函数：第一段写动作，第二段写清楚何时更新、什么时候不改；多个结果用 `@retval`，每个值一行，已变更的写在最前，其余按失败次序；描述与标签组之间空一行，标签之间不空行，`@note` 写判断次序。会抛的诊断函数（如 `ValidatePosition`）第一句写「……时抛出 `std::out_of_range`」，不写「检查……是否……」。
- 函数体注释可以作函数头的起点：第一句作简要描述，第二句作 `@return` 或 `@retval` 的说明；函数头要补返回值。对照例见 `source/07-comments/examples/declaration-function.md`。
- `@throws` 必须与 `source/08-exceptions/01-throw-rules.md` 一致；不抛异常的函数不写。
- 私有函数同样写契约，不能默认调用者知道前置条件；输出参数标 `[out]`，既读又写标 `[in,out]`。
- `std::formatter<T>` 特化的 `parse` 与 `format` 也按本节写：`parse` 写接受的格式与失败方式，`format` 写「把…格式化后写入输出上下文」这类职责句；具体输出形态由测试与读者正文承担，不重复进源码注释；不因为位于模板特化里就省略。

### 实现：阶段边界与为什么

`.cpp` / `.cc` 里，函数体用 `//`，不用 `///`：体内的 `///` 会接到该函数的 Doxygen 详细说明后面，成为误导性文档。重要函数按空行分段，每一段上方写一句 `//`。`//` 里的枚举值不包反引号，反引号只留给声明注释；一句赋值、单表达式函数（如 `IsFull`）不写注释；多分支函数里的拒绝与成功写入按下面两句写。只写删掉会让下一次修改得到错误结果、而代码本身看不出的内容。

拒绝与写入分支的默认格式是两句：

```cpp
// 检查传入状态是否为空。传入状态为空时，格子保持原状态。
if (state == CellState::kEmpty) {
  return PlaceResult::kRejected;
}
```

- 第一句「检查…是否…。」写这一支在检查什么；第二句「<条件>时，<结果>。」写条件成立后的结果。第二句的主语不能省到读不出：条件与结果主语不同时写出结果的主语（如「传入状态为空时，格子保持原状态」），主语相同时承前省略（如「格子是 X 或 O 时，保持原状态」）。
- 两句之间用句号；第二句内部条件与结果之间用逗号（复句内分句的停顿，GB/T 15834-2011 4.4.3.1），不写成两个句号。
- 同一函数内用词一致：`保持原状态`、`更新为传入状态`、`格子是 X 或 O`；不写 `保持原状`、`已有状态`、`变为已占用`。
- 只有当理由不在条件本身（次序依赖、防御性分支、调用方破坏前置条件）时，才用一句「为什么」代替两句，例如「终局是正常结果，先于棋盘检查」。
- 多条独立拒绝（如 `CheckPlaceable`）：每个 `if` 上一行两句，写检查什么、条件成立后格子或棋盘怎样；不同条件的 `if` 不合并成一句，即使后果相同。
- 成功写入的上一行两句：先写检查落点为空，再写更新结果。
- 只有次序依赖的一对 `if`（如 `GetWinner`、`JudgeAfterPlace`）：第一组上方一句说明次序为什么不能反，第二个 `if` 不复制同一句。
- 循环上方已经有阶段说明时，循环里的 `if` 不再加一行。
- `HasLine`、`IsFull` 这类单表达式不加；`GetWinner` 里的次序判断只在它真的解释「为什么先判胜」时留一句。
- 函数体里的关键局部声明（查表、分派表、缓存）上方写一句它是什么、覆盖哪些情况；表项内部的分组注释保留，不逐行翻译。

大型工程的共识是解释意图而不是逐步翻译：[Google C++ Style Guide](https://google.github.io/styleguide/cppguide.html#Implementation_Comments) 要求注释解释代码在做什么，不描述代码本身；[LLVM Coding Standards](https://www.llvm.org/docs/CodingStandards.html#commenting) 要求写意图与理由。阶段注释写的就是这两类信息。

中文句式按 GB/T 15834-2011《标点符号用法》4.4.3.1（复句内分句之间用逗号）、4.1.3.1（句号用于句子末尾）与阮一峰《中文技术文档的写作规范》（主动句、主语明确、句子短）写；与 NL.1「不在注释里重复代码」的张力，用「理由不在条件本身时用一句为什么」消解。

典型位置：

- 次序依赖：先判胜再判满，否则最后一子会变成平局。
- 类型收窄与解析：先按 64 位读再收窄；解析失败后必须丢掉整行。
- 三种拒绝都在赋值前返回，棋盘保持原样。
- 状态不变量、外部格式、回退路径、刻意重复。
- 共享方式：`thread_local` 之类的可见性。
- 关键局部表：表覆盖哪几类情况、编号按什么顺序；表项不再逐行解释。

循环体里逐行复述 `push_back`、`return` 的注释一律删；不写变更史、外部资料路径和注释掉的代码。CMake 的契约注释不在这里，写法见 `../../engineering/cmake/01-targets/01-rules.md`。

### 长度预算

| 层 | 行数 | 第一句 | 写什么 |
| --- | --- | --- | --- |
| 文件头 | 3–7（实现文件 2） | `@file` 文件名 + `@brief` 一句话 | 本文件由哪几部分组成 |
| 类型注释 | 2–14 | 名词短语：这个类型或取值是什么 | 只有类的不变量与生命周期 |
| 特殊成员 | 1–3 | 标签（默认/拷贝/移动构造函数、析构函数） | 后置条件或职责 |
| 函数注释 | 3–10（按标签数放宽） | 正常返回什么、失败时返回或抛什么、检查什么 | 每个参数、返回值与失败方式 |
| 无标签函数 | 2 | 两段：后置条件/职责，再补边界 | 仅限构造、析构、`void` 无参数 |
| 数据成员 | 上一行 1 句（`/// 名词：约定`） | 这个成员是什么；只属于它的轴向、哨兵或所有权 | 只写成员自身，不重复类注释的初值与状态迁移 |
| 实现注释 | 每个空行阶段 1 句 | 边界、失败后果或为什么停在这里 | `//`，只给重要函数 |

## 结构：放在哪一层、哪一行

- 文件头与声明注释用设置里选定的符号（默认 `///`，也可 `/** ... */`）：头文件里的类型、函数声明、枚举项、公开与私有数据成员，以及文件头的 `@file`/`@brief` 块。调用方和 Doxygen 从这里取契约。
- `///<` 只给枚举项和 `struct` 短字段的行尾；不要写在赋值、`break` 或普通语句后面。
- `//` 给函数体内的阶段说明、局部变量、守卫理由和普通语句行尾；这些注释不接 Doxygen 文档。
- `//` 也给工具指令与别种文件：`// NOLINTNEXTLINE(...)`、`#endif  // MACRO`，以及 CMake、YAML 等非 C++ 文件。
- 判断看位置：声明写契约，用选定的文档符号；实现写理由，用 `//`。
- 位置固定：文件头在最上方；类型注释紧贴类型声明；特殊成员（构造、析构、拷贝与移动）排在其他函数之前；函数注释紧贴函数声明；数据成员的主注释紧贴声明上一行，不写行尾补充。
- 类数据成员（含私有）的主注释用 `///`；行尾 `///<` 只给枚举项和 `struct` 的短字段。
- 注释和它说明的声明之间不留空行；同一个声明块内，空行只用来分组。

### 文件头

每个手写源文件开头写一段 doxygen 文件头：第一行写 `@file <文件名>`，第二行写 `@brief` 一句话说明这个文件定义或实现什么，用一行空注释隔开后，只写本文件自己的组成部分或边界。类型定义型头文件写「…相关类型定义。」，空行后以「封装了」起句，逐项写「中文概念 `类型名`」，顺序与声明一致；其他头文件写本文件定义什么，实现文件以「实现」收句。不写「文件包含」这类标签，也不写行为清单。`@file` 的参数必须与文件名逐字相同，检查器会核对。`@brief` 始终写出；`@author`、`@date`、`@copyright`、`@version` 的开关出厂打开，只有填了非空值才写出，空值整条省略；作者、年份和变更史按团队约定填写，不填就不出现在源码里。删掉把读者指去另一个头文件、另一个目录或另一层的句子，也删掉「这一层不负责什么」。不写作者、版权年份、变更日志和外部资料路径。

```cpp
/// @file cell.h
/// @brief 格子相关类型定义。
///
/// 封装了格子的状态枚举 `CellState` 以及格子实体 `Cell`。
```

选择块注释时，同一段写成：

```cpp
/**
 * @file cell.h
 * @brief 格子相关类型定义。
 *
 * 封装了格子的状态枚举 `CellState` 以及格子实体 `Cell`。
 */
```

- C++ 源文件用以上格式；CMake 用 `#`，YAML/JSON 用 `#`。
- 超过约 200 行的文件用空行分成几节，每节的说明写在一行 `///` 上，不画装饰线。
- 文件头 3–7 行，实现文件可只有 `@file` 与 `@brief` 两行；`@file` 与 `@brief` 各占一行，后面只写本文件的范围与组成，不写实现步骤、作者和变更史。

## 版式：符号、宽度与标签

- 注释符号在插件设置里选择：`///` 是默认写法，`/** ... */` 是另一种 Doxygen 写法；文件头与声明注释统一用同一种，函数体内仍只用 `//`。块注释每行以 ` * ` 对齐，收尾单独一行 ` */`。
- 行宽跟文件最近的 `.clang-format` 的 `ColumnLimit` 走：从文件所在目录向上查找，到工程根为止；都没有时按 Google 默认 80 列，中文按两列计。`checking-comments.mjs` 按同一规则取宽度。
- Doxygen 文档块：摘要与详细描述之间空一行；段落之间空一行；详细描述与标签块之间空一行；标签之间不空行。`@param`、`@retval`、`@return`、`@throws`、`@note` 连续排列，不插空 `///` 行。
- 注释换行：一句一行；超过列宽在分号或逗号处分句，续行与正文同缩进；标签描述尽量单行，超宽时在分句处断，续行相对标签文字缩进两格；不把一句话拆成一个词一行。
- 列表：同一段注释要列两种以上情况时，先写一句总起句说明这些项共同描述什么，紧接列表（中间不空行），每项一行；列表项比正文再缩进两格，让总起句与各项在源码里就能看出层级：Doxygen 写 `///   - `，块注释写 ` *   - `；注释整体有缩进时，列表项随正文一起平移。列表后按段落需要留空行。返回值列表（`@retval`）例外，可直接列值。`checking-comments.mjs` 会报 `list-indent`。
- 行尾注释与代码之间空两格；`///<` 只接在枚举项和 `struct` 短字段声明行尾。
- `@param`、`@return`、`@throws` 标签保持英文；`@param` 后先写参数名，再写一句。
- `TODO:` 后先写定位（阶段名或 issue 号），再写一个短横线，再写动作；不写 `TODO(某人)`，不写没有动作的 TODO。
- `.clang-format`、`.clang-tidy`、`.clangd`、CMake 的配置项旁边写「为什么这样设」，不写「这一项是什么」；配置注释贴在被解释的键上方。
- 禁止：大段表格、装饰图案、表情；外部资料路径、跨仓库引用、团队流程；注释掉的代码；注释元叙述（「其余内容见某处」「两处不重复」）。
- `///` 与 `@param` 不进入 `.qmd`、YAML、CSS。
- 函数体内不写 `///` 或 `/** ... */`；`//` 用于实现说明与 `// NOLINTNEXTLINE(...)` 这类工具指令。

## 措辞：删复述，统一句式

- 类型第一句是名词短语；布尔查询与 `operator==` 用「检查…是否…」；普通函数第一句写结果、失败方式或检查项。
- 特殊成员保留标签（`默认构造函数：`、`析构函数：` 等），但禁止只写「构造函数：创建对象」这类没有后置条件或职责的句子，也禁止复述类名、签名、成员清单。
- 禁止在类型注释里写领域尺寸（3×3、九个格子、边长）；尺寸由成员声明和常量表达。
- 禁止把成员功能清单按声明顺序抄一遍；函数契约写在各自函数上。
- 同一事实只写一处：声明注释、实现注释、书稿和 README 不各讲一遍。
- 删掉注释后读者不会做错事、或注释只重复签名时，删；但内容节要求保留的后置条件、类级生命周期、轴向和哨兵不在此列。
- 只改注释时仍走第 3、4 步，然后回读：文件头 → 类型（名词短语 + 只有类的不变量与生命周期）→ 特殊成员（标签 + 后置条件/职责）→ 函数（结果/失败方式/检查项 + 参数）→ 数据成员（只读上一行 `///`：名词 + 全角冒号 + 约定；行尾不应有注释）→ 实现（每个空行阶段的边界或理由）→ 术语与新符号是否真实存在 → 运行 `checking-comments.mjs` 兜底。
- 注释写给维护者，正文写给读者；设计理由、方案比较与算法取舍写在正文或实现注释里，公开接口只留契约。
- 禁止用注释代替类型、`const` 或 `[[nodiscard]]`。

### 术语与用词

`source/07-comments/glossary/comment-terms.md` 列「位置/坐标」「格子/棋盘」「更新/写入」「副本」「越界」与 `cell.h`/`cell.cpp` 这一组文件的用词。

- 领域行话第一次出现时写通用说法；「一次落子」就写全，不缩成行话简称；电脑的回应写「回应落子」，不写「应手」。不假定读者读过书稿或上一章；同一文件只留一个叫法。
- 类型与函数的第一句不能用未解释的行话代替定义。先写读者能核实的动作或对象，再补项目里的简称。
