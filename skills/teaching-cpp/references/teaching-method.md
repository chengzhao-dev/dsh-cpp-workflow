# 章节结构与讲解顺序

一章只解决一个读者任务。结构服务于这个任务，不服务于“把所有语法讲全”。

## 先定读者任务

写正文前先填三句话：

- 读者现在会什么：前置知识，具体到能写出的代码。
- 读完能做什么：一个可观察的动作，例如“能写一个用 `std::vector` 统计成绩的程序”。
- 怎么算做到：一个练习、一个测试或一段可运行输出。

任务太大时拆章。例如“学会面向对象”不是一章能完成的任务；“用 `class` 封装一个带不变量的计数器”才是。

## 概念章节的统一顺序

1. **引言**：这一章解决什么问题，读者最后能做什么。
2. **前置**：需要哪些已学概念；没有讲过的先补链接或补一节。
3. **问题**：用一个具体场景暴露“现在的写法不够”。
4. **心智模型**：用图、类比或内存示意解释“为什么这样设计”，先于语法细节。
5. **最小示例**：完整、可运行、只演示一个点。
6. **一个变化点**：改一个条件，让读者看到规则的边界。
7. **解释**：逐行讲关键语句，不逐字翻译语法。
8. **编译运行**：给出命令、实际输出、失败时的表现。
9. **验证**：读者怎么自己确认结果正确。
10. **常见错误**：真实会犯的错，给错误信息和修法。
11. **练习**：一到三道，覆盖本章任务，不引入未讲概念。
12. **小结**：三到五条，回扣心智模型，不重复目录。

顺序可以压缩，但不能跳过“问题 → 心智模型 → 示例”。没有问题的语法讲解会让读者不知道为什么需要它。

## 心智模型先于语法

- 讲指针前先讲“地址与对象”；讲引用前先讲“别名”；讲移动前先讲“资源所有权”。
- 用一张图或一段内存布局说明，比先列十条规则有效。
- 类比只用一个，讲完就回到 C++ 术语；不要用三个类比互相打架。
- 明确模型的边界：“栈/堆”是常见实现的简化，不是标准规定的存储分类。

## 示例的四种类型

| 类型 | 作用 | 要求 |
| --- | --- | --- |
| 最小完整例 | 展示一个概念的最小可运行程序 | 有 `main`，能编译运行，输出真实 |
| 片段 | 聚焦一行/一个函数 | 以 `// 片段` 开头，说明上下文和省略部分 |
| 对比例 | 展示“这样写会错，那样写对” | 错误例明确标错，给真实报错或行为 |
| 综合例 | 把本章概念放进一个小项目 | 仍只增加一个主要变化点，不引入未讲工具 |

一个例子只承担一个教学目的。需要同时讲“为什么用 `vector`”和“怎么用迭代器”时，拆成两个例子。

## 规则条目的写法

每条规则按五段写，能省则省，但不能只有结论：

1. **建议**：一句话说怎么做。
2. **原因**：为什么，关联到心智模型或失败模式。
3. **正例**：最小代码。
4. **边界**：什么时候不适用。
5. **验证**：编译器警告、测试或可观察输出。

反例：

> 不要用裸指针。

正例：

> 需要独占所有权时用 `std::unique_ptr<T>`。它把释放放进析构函数，异常路径也不会泄漏；只有需要共享所有权时才用 `std::shared_ptr<T>`，并用 `std::weak_ptr` 打破循环。验证：用 ASan 跑一次异常路径，确认没有泄漏报告。

## 来源与口径

- 标准行为以 cppreference 或标准草案为准；编译器扩展单独标注。
- 不写“某编译器支持”而不写版本；版本相关特性给最低标准版本和实测编译器版本。
- 输出、报错、性能数字必须来自实际运行；不能运行的示例标“示意”，并说明缺什么。
- 引用外部文章时给链接和访问日期；不把二手结论当标准原文。

## 练习设计

- 练习覆盖本章读者任务，不考未讲概念。
- 一道“照着改”，一道“独立写”，一道“找错/解释”；按章节难度取舍。
- 给验收标准，不只给题目：“输出应为……”“越界时应抛……”。
- 不提供完整答案在正文同一屏；答案放章末或折叠块，避免读者先看答案。
- 练习代码也要能编译；至少给出起始骨架。

## 章节检查清单

- [ ] 读者任务一句话说清，练习能验收。
- [ ] 前置概念已讲或已链接。
- [ ] 先问题、再心智模型、再示例。
- [ ] 最小示例完整可运行，输出真实。
- [ ] 只引入一个变化点；超过就拆。
- [ ] 规则有原因、正例、边界、验证。
- [ ] 常见错误来自真实报错，不是编造。
- [ ] 练习不引入未讲概念，有验收标准。
- [ ] 小结回扣模型，不重复目录。
