# 示例验证

教程里的每一段代码都必须是“跑过的”，不是“看起来对”。验证分编译、运行、输出和边界四层。

## 编译基线

单个示例：

```bash
clang++ -std=c++20 -Wall -Wextra -Wpedantic -O2 example.cpp -o example
```

- 用 `-std=c++20`，不用 `gnu++20`；教学示例不依赖 GNU 扩展。
- `-Wall -Wextra` 是底线；`-Wpedantic` 帮忙发现非标准写法。
- 示例目录有 CMake 时，用项目构建，不手工绕过。
- 每个示例至少用声明支持的一个编译器跑过；跨平台章节用两个。
- 报错示例单独标记，不加入“全部通过”的验证集合。

## 片段与完整示例

- 完整示例：有 `int main()`，能单独编译运行，输出与正文一致。
- 片段：第一行 `// 片段`，说明所在文件、省略了什么、依赖哪些已定义的名称。
- 片段不假装能编译；但把片段拼回完整示例后必须能编译。
- 正文展示的代码块与 `code/` 下的文件保持一致；改一处时两边一起改。
- 不把整份 200 行文件贴进正文；只贴关键 10–30 行，其余给路径。

## 输出测量

- 输出必须来自实际运行；不要凭记忆写“Hello, world!”以外的结果。
- 浮点输出写明格式和精度；不同标准库的默认格式可能不同。
- 性能数字写明硬件、编译器、优化级别和输入规模；没有这些条件就不写数字。
- 错误信息保留原始文本，包括编译器名和版本；不要改写成“大概会报错”。
- 交互式程序用固定输入重定向验证，不靠手工敲：

```bash
printf '1 2\n' | ./build/clang/bin/app
```

## 代码块长度

- 单块不超过 40 行；超过时按“声明 / 实现 / 调用”或“之前 / 之后”拆分。
- 一个代码块只讲一个变化点；需要对比时用两个块，不用一个块里塞两种写法。
- 长示例用“省略号”时，必须能说清省略的是重复代码还是无关代码；不要让读者猜。
- 缩进统一 2 空格或 4 空格，跟项目 `.clang-format` 一致；不要在同一章混用。

## 构建脚本

教学项目的脚本只做四件事：

1. 配置：`cmake -S . -B build -G Ninja -DCMAKE_CXX_COMPILER=clang++`
2. 构建：`cmake --build build`
3. 运行：`./build/bin/app`
4. 清理：删除 `build/`。

- 脚本参数化编译器和构建目录，不写死本机路径。
- 构建失败时保留完整错误，不 `|| true` 吞掉。
- 教学脚本可以比工程脚本简单，但不能假装成功；退出码要真实。
- 多文件/库示例的 CMake 用 target-based 写法，和 `building-cpp` 一致。

## CMake 的教学顺序

1. 单文件：`add_executable(app main.cpp)`。
2. 加标准：`target_compile_features(app PRIVATE cxx_std_20)`。
3. 多文件：把 `src/*.cpp` 列进 `add_executable`。
4. 公共头：`target_include_directories(app PRIVATE include)`。
5. 库：`add_library(greeting ...)` + `target_link_libraries(app PRIVATE greeting)`。
6. 测试：`enable_testing()` + `add_test`。
7. 安装/导出：只在项目确实需要分发时讲。

- 教学小项目可以用 `file(GLOB CONFIGURE_DEPENDS ...)` 减少“加文件要改 CMake”的干扰，但要明确标注“仅教学简化”；工程项目显式列源文件。
- 不把 `-stdlib=libc++` 写进全局 `CMAKE_CXX_FLAGS`；需要时按 target 设置，并保证 clangd 用同一套标准库。
- CMake 版本写最低可用版本（3.20），不要写读者本机的最新版。

## 自动验证

仓库有验证脚本时，脚本至少检查：

- 每个完整示例能编译（C++20 + 警告）。
- 每个完整示例能运行，退出码为 0（错误示例除外）。
- 输出与正文中的“输出块”一致，或至少包含关键行。
- 片段有 `// 片段` 标记；完整示例有 `main`。
- 代码块不超过长度上限。

脚本报告失败时给文件、行号、命令和实际输出；不要只打印“验证失败”。

## 版本与编译器

- 标注特性的最低标准版本：`C++20`、`C++23`；不要把 C++23 特性写进 C++20 章节。
- 标注实测编译器及版本：例如 `clang++ 21.1.8`、`g++ 13.2`。
- 标准库实现差异单独说明：`std::format` 在 libstdc++ 13 / libc++ 14 起可用；更早版本需要替代方案。
- 不用“最新编译器都支持”代替版本号。
