# 术语、版本与来源

教程里的术语一旦混用，读者就会把两个概念当成一个。首次出现给中英文，之后只用一个译名。

## 核心术语

| 英文 | 统一译名 | 说明 | 不写 |
| --- | --- | --- | --- |
| declaration | 声明 | 让名字可见，不分配存储 | 定义 |
| definition | 定义 | 分配存储或给出函数体 | 声明 |
| translation unit | 翻译单元 | 一个源文件加它包含的头，预处理后的结果 | 编译单元（可接受，但前后统一） |
| object | 对象 | 某类型的一块存储 | 实例（讲类对象时也统一用对象） |
| value | 值 | 可复制、比较、传递的内容 | 数值（数值只是值的一种） |
| reference | 引用 | 已有对象的别名 | 指针 |
| pointer | 指针 | 存地址的对象，可为空 | 引用 |
| ownership | 所有权 | 谁负责释放资源 | 所属权 |
| RAII | 资源获取即初始化 | 用对象生存期管理资源 | 资源管理（太泛） |
| invariant | 不变量 | 对象始终满足的条件 | 约束（约束另有含义） |
| contract | 合同 | 调用方与被调方的约定 | 契约（可接受，但统一） |
| undefined behavior | 未定义行为 | 标准不规定结果 | 未定义（省略“行为”） |
| implementation-defined | 实现定义行为 | 标准允许实现选择并记录 | 未定义行为 |
| half-open range | 半开区间 | `[first, last)` | 左闭右闭 |
| out-parameter | 输出参数 | 通过引用/指针写回结果 | 传出参数 |
| aggregate | 聚合 | 无用户构造、无私有成员的简单结构 | 集合 |
| template instantiation | 模板实例化 | 用具体类型生成代码 | 模板展开 |
| overload | 重载 | 同名不同参数 | 覆盖 |
| override | 覆盖 | 派生类替换虚函数 | 重载 |
| linkage | 链接性 | 名字能否跨翻译单元使用 | 连接 |
| ODR | 单一定义规则 | 一个实体只能定义一次 | — |
| compile database | 编译数据库 | `compile_commands.json` | 编译命令表 |
| target | 构建目标 | CMake 的库/可执行文件 | 项目（项目是更上层） |
| toolchain | 工具链 | 编译器、链接器、构建工具 | 编译器（工具链更大） |
| sanitizer | 检查器 | ASan/UBSan/TSan 等运行期检查 | 消毒器 |
| ABI | 应用二进制接口 | 调用约定、布局、符号 | 接口（API 不同） |
| binding | 绑定 | Python/C++ 之间的调用层 | 插件 |

## 容易混淆的对

- **声明 vs 定义**：`int f(int);` 是声明；`int f(int x) { return x; }` 是定义。
- **引用 vs 指针**：引用必须绑定且不能改绑；指针可为空、可改指向。
- **拷贝 vs 移动**：拷贝保留源对象；移动把资源转走，源对象进入有效但未指定状态。
- **重载 vs 覆盖**：重载是编译期按参数选同名函数；覆盖是运行期虚函数分派。
- **未定义行为 vs 实现定义行为**：前者没有保证；后者实现必须选一个并记录。
- **编译错误 vs 链接错误**：前者在翻译单元内；后者在符号解析时。
- **静态库 vs 共享库**：前者链接时复制目标文件；后者运行时加载。
- **API vs ABI**：API 是源码级接口；ABI 是二进制级布局和调用约定。

## 版本标注

| 标准 | 教程中的用法 |
| --- | --- |
| C++11 | 已有项目兼容时标注；不作为新代码默认 |
| C++14 | 变量模板、泛型 lambda；标注即可 |
| C++17 | `std::optional`、`std::variant`、`if constexpr`、结构化绑定 |
| C++20 | 本教程默认：概念、`std::span`、`std::format`、范围、`contains` |
| C++23 | 明确标注：`std::expected`、`std::print`、`std::stacktrace`；C++20 章节不用 |

- 写“C++20 起可用”，不写“新标准支持”。
- 同一特性在不同标准库实现的时间不同，单独标注实现版本。
- 不用 C++23 特性写 C++20 示例，即使编译器默认支持。
- 版本标签放在首次出现处，不每段重复。

## 来源优先级

1. ISO C++ 标准草案（eel.is/c++draft 或WG21 文档）。
2. cppreference（查行为、复杂度、版本）。
3. 编译器/标准库官方文档（查实现差异、扩展）。
4. 高质量书籍/文章（查教学表达，不替代标准）。

- 引用链接给完整 URL 和访问日期。
- 标准行为与编译器扩展分开写；扩展标“非标准”。
- 不把博客结论当标准；有冲突时以标准和实测为准。
- 性能数字、报错文本、输出必须来自实测；不能实测时标“示意”并说明条件。

## 写作口径

- 用“你”称呼读者，不用“我们”“大家”。
- 命令用代码块，给出工作目录和预期输出。
- 不写“很简单”“众所周知”；直接给步骤和原因。
- 一个段落一个主题；长段落拆列表。
- 中文标点统一全角；代码、类型、命令用反引号。
- 首次出现的缩写给全称：UB（undefined behavior，未定义行为）。

- [ ] 声明/定义、引用/指针、重载/覆盖没有混用。

- [ ] 来源可追溯，标准与扩展分开。
- [ ] 输出、报错、性能数字来自实测或有“示意”标记。
