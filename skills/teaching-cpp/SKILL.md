# teaching-cpp

教一个概念，不是把语法条目堆给读者。每一节先回答“读者要完成什么”，再给最小可运行例子，最后用一个变化点把知识变成能力。

## 先选走法

| 走法 | 什么时候用 | 怎么做 |
| --- | --- | --- |
| 整章 | 新章节、重排一章、读者任务变了 | 按 1 → 2 → 3 → 4 走完；先读 `references/teaching-method.md` |
| 一节 | 只补一个例子、修一段解释、换一道练习 | 先判断属于哪一步，只改这一节；不动章节顺序 |
| 全局 | 术语、版本口径、示例验证规则变化 | 先改 `references/` 的规则，再批量修章节；不要逐章打补丁 |

拿不准先用“一节”。发现读者任务或概念顺序变了，退回“整章”。

## 四步

| 步 | 名称 | 一句话 |
| --- | --- | --- |
| 1 | 定读者任务 | 读完这一节，读者能独立完成哪一个可观察的动作？ |
| 2 | 定概念顺序 | 前置概念是否已讲？心智模型是否先于语法细节？ |
| 3 | 定示例 | 最小完整例子是什么？只改变哪一个点？ |
| 4 | 验证示例 | 真编译、真运行、真测量输出，失败就改例子。 |

## 硬规则

- 每个 C++ 示例必须能用 C++20 编译：`-std=c++20 -Wall -Wextra`，除非章节明确标为“错误示例”。
- 完整示例有 `int main()`；片段以 `// 片段` 开头，并说明省略了什么。
- 输出是实际运行得到的，不凭记忆写；版本相关的特性标注最低标准版本。
- 一个示例只引入一个变化点；需要两个变化时拆成两个例子。
- 单个代码块不超过 40 行；超过时拆成“声明 / 实现 / 调用”或“之前 / 之后”。
- 代码块应当能独立阅读：不依赖上一段没有展示的变量，不依赖“省略号”猜上下文。
- 先展示可运行的最小版本，再解释语法；不要先讲十分钟规则再给例子。
- 错误示例要明确标“错误”，并给出编译器/运行时的实际表现，不伪造报错。
- 不写“显而易见”“简单来说”代替解释；读者卡住的地方要展开。
- 术语首次出现给中英文，之后统一用一个译名；不混用“对象/实例”“声明/定义”。

## 完成判据

- 读者任务可以用一个练习或验收句检验。
- 概念顺序没有跳步：每个新术语都能在前文找到定义。
- 每个示例都真实编译、运行过，输出与正文一致。
- 片段标记、版本标注、错误示例标记齐全。
- 章节末尾有练习、常见错误和小结，练习能独立完成。
- 没有把项目专属类名、知识库路径、内部任务编号写进通用教程。

C++ 源码风格与构建约束分别以 `developing-cpp`、`building-cpp` 为准；本技能只决定“怎么讲”，不另外发明一套代码规则。
