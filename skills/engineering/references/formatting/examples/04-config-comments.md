# 正反例：配置文件注释

`runtime.config` 这类运行时配置一个键一项，注释规则见下节；句式与语言无关，下面用 TOML 举例。`.clang-format`、`.clang-tidy`、`.clangd`、`.editorconfig` 与 `.vscode/` 的固定值配置按 `developing-cpp` 的 `references/comments/02-style.md` 写。

## 键注释

**好**（完整文件）：

```toml
# 本仓 Python 与 Quarto 的运行时配置。
#
# 定义解释器路径、Python 与 Quarto 的最低版本。

# =================================== Python ===================================

# Python 解释器的完整路径：解释器不存在或不可执行时，检查脚本报错退出。
python_path = "D:/ProgramData/miniforge3/python.exe"

# Python 解释器的最低版本：解释器版本低于此值时，检查脚本报错退出。
python_min_version = "3.12"

# =================================== Quarto ===================================

# Quarto 的最低版本：已安装的 Quarto 低于此值时，检查脚本报错退出。
quarto_min_version = "1.10.19"
```

句式「对象：条件时，后果。」：对象与键名对得上，条件写清比较对象，后果写清谁报错、报什么；同类键取同一句式，便于并排核对。

**差**：

```toml
# python 路径
python_path = "D:/ProgramData/miniforge3/python.exe"
# 版本低于此值时报错退出
quarto_min_version = "1.10.19"
```

第一条复述键名；第二条没有比较对象与执行者。`sed` 取值、CI 步骤这类实现细节同样不写进注释：注释给的是读者要遵守的契约与违反后的后果。

## 注释语法

- TOML 配置只有 `#` 一种注释；`#` 后空一格，句末用句号。
- 注释紧贴键的上一行，键与注释之间不空行；不写行尾注释。
- 键块（注释 + 键）内部不空行，键块之间空一行。
- 文件有两个及以上对象时，每区第一行写一行 80 列等号横幅，标题居中，前后各空一行；`.editorconfig` 的横幅紧贴其下的节头，节按文件后缀分组，不按本仓目录命名。
- 数组键（用到时）：键名后换行，一项一行，收尾 `]` 顶格；不给数组项加行尾注释。

## 抬头

标题不是必需：需要交代文件整体用途时写一行标题，第二行写 `#`，其后一到两行写文件内容或例外（本技能的 `.clang-format` 资产只有标题、`#` 与一行用途）；只写内容，不写取舍理由、工具来源与跨文件关系；动词按文件性质取（定义、规定、约定），不要求统一用「定义」；本例的 `runtime.config` 写全三行。

## 模板

新建运行时配置时按下面的骨架写，替换尖括号内容；键名与取值按项目实际，分组与句式不变；多对象时按正例加区域横幅，等号补到 80 列。第三行的动词按「抬头」一节取，骨架用「定义」只是示例。模板只示意标量键，用到数组键时按「注释语法」末条写。标题按「抬头」一节的判断保留或删除。

```text
# <项目>的运行时配置。
#
# 定义<条目>。

# ============================== <对象> ==============================

# <对象>：<条件>时，<执行者>报错退出。
<键> = "<值>"

# <对象>：<条件>时，<执行者>报错退出。
<键> = "<值>"
```
