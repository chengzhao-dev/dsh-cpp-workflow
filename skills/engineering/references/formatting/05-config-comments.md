# 配置文件注释

配置分两类：运行时配置（如 `runtime.config`、`*.toml`、`*.ini`）一个键一项，注释写契约与后果；固定值配置（`.editorconfig`、`.clang-format`、`.clang-tidy`、`.clangd`、`.vscode/*.json`）的键与取值直白，注释写一句简短说明。

## 键注释

运行时配置的键注释用「对象：条件时，后果。」：对象与键名对得上，条件写清比较对象，后果写清谁报错、报什么；同类键取同一句式，便于并排核对。

**好**（完整文件）：

```toml
# 本工程的工具配置。
#
# 定义构建工具路径与最低版本。

# ================================ 构建 ================================

# 构建工具的可执行文件：路径不存在或不可执行时，检查脚本报错退出。
build_tool = "/usr/bin/ninja"

# 构建工具的最低版本：版本低于此值时，检查脚本报错退出。
build_tool_min_version = "1.11"
```

**差**：

```toml
# build tool 路径
build_tool = "/usr/bin/ninja"
# 版本低于此值时报错退出
build_tool_min_version = "1.11"
```

第一条复述键名；第二条没有比较对象与执行者。`sed` 取值、CI 步骤这类实现细节同样不写进注释：注释给的是读者要遵守的契约与违反后的后果。

## 注释语法

- TOML 配置只有 `#` 一种注释；`#` 后空一格，句末用句号。JSON 配置按 JSONC 用 `//`，`.clang-format` 等 YAML 用 `#`。
- 注释紧贴键的上一行，键与注释之间不空行；不写行尾注释。
- 键块（注释 + 键）内部不空行，键块之间空一行。
- 文件有两个及以上对象时，每区第一行写一行 80 列等号横幅，标题居中，前后各空一行；`.editorconfig` 的横幅紧贴其下的节头，节按文件后缀分组，不按本仓目录命名。
- 数组键（用到时）：键名后换行，一项一行，收尾 `]` 顶格；不给数组项加行尾注释。

## 抬头

标题不是必需：需要交代文件整体用途时写一行标题，第二行写 `#`，其后一到两行写文件内容或例外（`building-cpp` 的 `assets/config/.clang-format` 只有标题、`#` 与一行用途）；只写内容，不写取舍理由、工具来源与跨文件关系；动词按文件性质取（定义、规定、约定），不要求统一用「定义」。

## 固定值配置

键注释写一句简短的中文说明，如 `# 每级缩进 4 个空格。`、`# 换行符用 CRLF。`；不套运行时的「对象：条件时，后果。」，也不写「对象：取值。」的词典式短句。

**好**：

```text
# 每级缩进 4 个空格。
indent_size = 4

# 换行符用 CRLF，提交时由 .gitattributes 归一。
end_of_line = crlf
```

**差**：

```text
# 缩进配置：未按 4 个空格缩进时，clang-format 报错退出。
indent_size = 4
```

固定值配置没有运行时那样的错误后果，套用后果句式会凭空承诺一个不存在的检查。

## 模板

新建运行时配置时按下面的骨架写，替换尖括号内容；键名与取值按项目实际，分组与句式不变；多对象时按正例加区域横幅，等号补到 80 列。第三行的动词按「抬头」一节取，骨架用「定义」只是示例。模板只示意标量键，用到数组键时按「注释语法」末条写。

```text
# <项目>的<用途>配置。
#
# 定义<条目>。

# ============================== <对象> ==============================

# <对象>：<条件>时，<执行者>报错退出。
<键> = "<值>"

# <对象>：<条件>时，<执行者>报错退出。
<键> = "<值>"
```
