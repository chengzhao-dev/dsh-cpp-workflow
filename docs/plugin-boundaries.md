# 工作区边界

门禁只回答一个问题：当前会话是否处在一个已经声明 C++ 工作流的项目里。答案每次查询都重新计算，没有缓存，也没有常驻进程。

## 扫描范围

- 从 `cwd` 向上最多 64 层找 git 根（`.git` 文件或目录都算）。
- 从 `cwd` 到 git 根逐层找 `.agents/skills/cpp-workflow-project/SKILL.md`；找到最近的一份就停止向上找。向上查找时不看兄弟目录。
- 项目技能标记用来让仓库选择加入；一旦找到，源文件和 `CMakeLists.txt` 在这个 git 仓库的根下递归查找，不越过 git 根。
- 源文件扫描最多 12 层、4000 个目录项，先到先停。
- 跳过 `.git`、`node_modules`、`vendor`、`third_party`、`templates`、`build`、`temp`、`.cache`。
- 第一方证据是 `CMakeLists.txt`，或扩展名恰为 `.c`、`.cc`、`.cpp`、`.cxx`、`.h`、`.hh`、`.hpp`、`.hxx` 的文件。

两个条件必须同时成立：

1. 从 `cwd` 到 git 根的路径上存在项目技能标记。
2. 这个 git 仓库里有第一方 CMake 或 C++ 源文件。

## 八类情形

| 情形 | 结果 | 原因 |
| --- | --- | --- |
| 没有 `cwd`，或不在 git 检出里 | 不出现 | 没有可判定的工作区 |
| 没有项目技能，只有 `CMakeLists.txt`、散落的 `.cpp` 或注释里的 C++ 字样 | 不出现 | 缺少项目级声明 |
| 有项目技能，但没有第一方 C++ 或 CMake | 不出现 | 纯文档仓库、只复制模板的仓库不算工程 |
| 项目技能在 git 根之上，或会话停在仓库根而标记只在子目录 | 不出现 | 标记不在 `cwd` 到 git 根的路径上 |
| 进入标记所在的子目录，且源文件在同一 git 仓库内 | 出现两个技能 | 两个条件都成立 |
| 最近的项目技能存在，但源文件条件不成立 | 不出现，也不向父仓库命中 | 最近标记已经确定项目边界 |
| 项目技能在 `cwd` 到 git 根的路径上，且同一 git 仓库内有第一方源文件 | 出现 `developing-cpp` 与 `building-cpp` | 两个条件都成立 |
| 同一仓库里还有 Quarto 配置或其他语言工程 | 仍按上面两条判定 | `.qmd` 和非 C++ 文件不参与 |

搜索标记时不越过 git 根，也不看兄弟目录；找到标记后，源证据以这个 git 根为仓库边界，可以来自 marker 所在子目录之外的同一仓库。“不看兄弟目录”约束的是标记的向上查找，不把源证据缩到 marker 目录。一个仓库只有一份项目技能和一份 `environment.json`；项目技能由宿主自己的项目技能扫描看见，不由本包注册。

## 覆盖关系

插件技能的 rank 是 550。项目自己的 `.agents/skills` 技能 rank 是 200，用户级技能是 500，包内根技能是 600。项目里放同名的 `developing-cpp` 或 `building-cpp` 会盖住插件，项目模板禁止这么做。项目技能 `cpp-workflow-project` 是另一个名字，不冲突。

## get 与 abort

`list()` 返回空列表时，没有 candidate，`get()` 也不会被调用。`get()` 带 `cwd` 时重新过门禁；换到未声明的目录后，旧 candidate 不再可用。调用方传 `AbortSignal` 时，已经中止的查询返回空列表，而不是抛错。
