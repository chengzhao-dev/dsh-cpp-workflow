# 工作区边界

门禁只回答一个问题：当前会话是否处在一个已经声明 C++ 工作流的项目里。插件自己没有缓存，也没有常驻进程或定时器，每次被调用都重新扫描；宿主会把完成的目录按 `cwd`、作用域与修订号缓存，重算之前不会再调用这里。运行时的写盘与缓存边界见 [plugin-storage.md](plugin-storage.md)。

## 扫描范围

- 从 `cwd` 向上最多 64 层找 git 根（`.git` 文件或目录都算）。
- 从 `cwd` 到 git 根逐层找 `.agents/skills/cpp-workflow-project/SKILL.md`；找到最近的一份就停止向上找，不看兄弟目录。
- 项目技能标记就是仓库选择加入本工作流的唯一门禁。找到标记后不再扫描 `CMakeLists.txt` 或源文件，因此空的、只复制了模板的、以及还在设计阶段的仓库都能看到三个技能。
- 查找标记不越过 git 根。

## 边界情形

| 情形 | 结果 | 原因 |
| --- | --- | --- |
| 没有 `cwd`，或不在 git 检出里 | 不出现 | 没有可判定的工作区 |
| 没有项目技能，只有 `CMakeLists.txt`、散落的 `.cpp` 或注释里的 C++ 字样 | 不出现 | 缺少项目级声明 |
| 有项目技能，仓库里没有 CMake 或 C++ 源文件 | 出现三个技能 | 标记已经选择加入；轴为空时停在定构建 |
| 只复制了项目模板，还没有任何源文件 | 出现三个技能 | 同上，走新工程流程 |
| 项目技能在 git 根之上，或会话停在仓库根而标记只在子目录 | 不出现 | 标记不在 `cwd` 到 git 根的路径上 |
| 进入标记所在的子目录 | 出现三个技能 | 最近的标记决定项目边界 |
| 项目技能在 `cwd` 到 git 根的路径上，同一仓库里还有 Quarto 配置或其他语言工程 | 出现三个技能 | 标记只回答「是否选择加入」，不按文件类型再筛 |

搜索标记时不越过 git 根，也不看兄弟目录；一个仓库只有一份项目技能和一份 `environment.json`。项目技能由宿主自己的项目技能扫描看见，不由本包注册。门禁故意不检查源文件：C++ 工程在起步阶段常常还没有 `CMakeLists.txt`，要求源文件会把最需要工作流的新工程挡在外面。

## 覆盖关系

插件技能的 rank 是 550。宿主本地扫描的六档是：`.dsh/skills` 100、项目 `.agents/skills` 200、`customSkillDirs` 300、`user-dsh` 400、`user-agents` 500、包内根 `bundled` 600；近层同名先直接胜出，rank 只在同一层内决胜。项目或用户目录里放同名的 `developing-cpp`、`engineering` 或 `building-cpp` 都会盖住插件，项目模板禁止这么做，用户目录里的旧副本也因此不会被误当成本包提供的能力；本包不注册根技能，只与 550 这一档比较。项目技能 `cpp-workflow-project` 是另一个名字，不冲突。

## get 与 abort

`list()` 返回空列表时，没有 candidate，`get()` 也不会被调用。只有调用方传 `cwd` 时才重查门禁；不传时继续服务已经加载的 candidate。插件本身不抛错：调用方传 `AbortSignal` 时，已中止的 `list()` 返回空列表，`get()` 返回 `undefined`；宿主在调用前后检查 abort 并抛出 `AbortError`，所以用户侧看到的仍是中止。
